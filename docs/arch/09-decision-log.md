# 09. 결정 로그 (Architecture Decision Log)

상위: `아키텍처.md` / 계획 결정 D1~D11 은 `docs/plan/01` §확정 설계 결정 (참조, 중복 서술하지 않음).
이 로그는 **아키텍처 계층의 결정**만 담는다. 각 항목 형식: 결정 / 맥락 / 근거 / 결과 / 관련.

---

## AD-01. 아키텍처 스타일 = 모듈러 모놀리스

- **결정**: 단일 프로세스 · 계층형 · in-process 함수 호출. L0(leaf) → L4(entrypoint) 5계층.
- **맥락**: 요구는 "검색어 1개 → pptx 1개", 동시 사용자 1명, 로컬 실행.
- **근거**: 런타임 분할은 직렬화·운영 비용만 늘리고 얻는 것이 없다. 계층 분리는 `text`/`pptx`/`crawl` 축을
  서로 모르게 하기 위한 것이며, 이는 테스트 가능성(네트워크 없이 pptx 테스트)과 교체 가능성(소스/템플릿)의 전제다.
- **결과**: 계층 위반은 `test_imports.py` 로 기계적 차단. `pipeline.py` 만 세 축을 조립.
- **관련**: 계획 D1, D6, D10 / `02 §1–4`.

## AD-02. 미채택 인프라 (마이크로서비스·큐·이벤트버스·DB·캐시서버)

- **결정**: 전부 채택하지 않는다.
- **근거(각 한 줄)**: MS — 프로세스 1개라 분할 이득 < 비용 / 큐 — 동시성이 0이라 흡수 대상 없음 /
  이벤트버스 — 발행·구독이 같은 호출 스택 / DB·ORM — 영속 대상이 파일 1종 / 캐시서버 — dict 1개로 충분.
- **결과**: 저장소는 파일 시스템, 상태는 프로세스 메모리, 조립은 함수 호출.
- **관련**: `아키텍처.md §1 미채택 표`.

## AD-03. 예외 트리 루트를 `errors.py` 로 분리 (계획서 02 문구 확장)

- **결정**: `Lyrics2PptxError`(루트, `errors.py`) ← `SourceError`(수집, `crawl/base.py`),
  `EmptyLyricsError`, `TemplateStructureError`, `OutputWriteError`, `ConfigError`.
- **맥락**: 계획서 02 §코딩규칙은 "도메인 예외는 `crawl/base.py` 의 `SourceError` 하위로만"이라 적었다.
  그러나 `EmptyLyricsError`(텍스트/빌드)와 `TemplateStructureError`(pptx)는 수집 예외가 아니다.
- **근거**: 그것들을 `crawl/base.py` 에 두면 `text`/`pptx` 가 `crawl` 을 import 해 P1~P4 를 위반한다.
  루트를 leaf 모듈로 빼면 세 축이 `errors.py` 만 공유하고 서로를 모른다.
- **결과**: 계획서 02 의 좁은 문구를 **대체(supersede)** 한다. `SourceError` 는 "수집 예외의 상위"로 의미가 좁혀진다.
- **관련**: `03 §2–3`, P1~P4.

## AD-04. 슬라이드 복제 = 방식 A (`<p:sld>` 전체 deepcopy → 신규 파트 등록)

- **결정**: 계획서 05 를 그대로 확정. 방식 B(`add_slide` + 도형 이동) 기각.
- **근거**: `<p:sld>` 전체를 복사하면 `slideLayout` rel 과 `<p:bg>` 가 자동 보존된다. B 는 배경을
  다시 붙이는 추가 로직이 필요하고 누락 위험이 크다.
- **결과**: 복제 로직의 정확한 호출 형태는 `_make_slide_part()` 한 함수에 격리. 계약은 "PPTX 를 열면 배경이 그대로".
- **관련**: 계획 D6 / `04 §3`.

## AD-05. 수집은 어댑터, 실패는 기능 차단이 아님

- **결정**: 소스는 `Source` 프로토콜 + `SOURCES` 레지스트리. 직접 입력 경로는 수집을 완전히 우회.
- **근거**: 소스 미확정·차단·커버리지 부족이 핵심 기능(pptx 생성)을 막아서는 안 된다.
- **결과**: `pipeline.run(raw_text=...)` 는 네트워크를 호출하지 않는다(테스트로 보장).
- **관련**: 계획 D1, R3, R4 / `01 §4`, `06`.

## AD-06. media 파트 재사용 — 중복 등록 금지 (R-M1~R-M5)

- **결정**: 이미지 파트를 새로 만들지 않는다. 모든 image rel 은 `relate_to(rel.target_part, ...)` 로 기존 파트 재사용.
- **맥락**: media 20개(총 37MB 대부분)를 출력 슬라이드 수만큼 복제하면 파일이 수백 MB 로 팽창한다.
- **근거**: `relate_to` 는 (reltype, 대상) 동일 시 기존 rId 를 반환 → 20장이 같은 이미지를 참조해도 파트는 1개.
- **결과**: 산출 크기 ≈ 템플릿 크기. 검증: 복제 후 `ppt/media/*` 개수 == 템플릿과 동일.
- **관련**: `04 §3.4`.

## AD-07. 텍스트 서식 = 첫 run `rPr` 상속 + `normAutofit` 위임 (계획서 D8 확정)

- **결정**: 슬라이드별 첫 run `rPr` 을 deepcopy 스냅샷(직렬화 bytes)해 새 문단에 적용. 크기 고정, `normAutofit` 만 켬.
- **근거**: 텍스트 픽셀 폭을 정확히 측정할 수 없고, `sz` 가 슬라이드마다 다르다(6000~7200).
  렌더러에 축소를 위임하는 편이 "2줄 유지"를 지키면서 단순하다.
- **결과**: 직접 축소/줄바꿈 삽입은 기각. F1~F8 규칙 고정. 위치(`a:off`/`a:ext`)·anchor 는 불변.
- **관련**: 계획 D8, R5, Q3 / `04 §4`.

## AD-08. notesSlide 미복제 (`keep_notes` 옵션으로만 전환)

- **결정**: 복제하지 않는다. `remap_relationships` 에서 `RT_NOTES_SLIDE` skip.
- **근거**: 템플릿 노트는 원곡 전용이라 다른 곡 슬라이드에 붙으면 오정보가 된다.
- **결과**: `BuildResult.dropped_notes_count == N`. `LYRICS2PPTX_KEEP_NOTES=1` 로 전환 가능(기본 off).
- **관련**: 계획 D9, R8, Q4 / `04 §3.6`.

## AD-09. 오류 → 사용자 메시지 변환은 `pipeline.describe_error()` 단일 지점

- **결정**: 예외 → (code, message, http_status, recoverable) 변환 표를 한 함수에만 둔다.
- **근거**: CLI 와 웹이 다른 문구를 내면 계획서 03/06 의 실패 표와 어긋난다. 변환 지점이 둘이면 반드시 표류한다.
- **결과**: `webapp` 은 `http_status`/`code` 를 그대로 쓰고, `cli` 는 `message`/종료코드만 쓴다. 스택은 로그에만.
- **관련**: `03 §4`, `05 §2.3`.

## AD-10. 배경 순환 `bg_index = pool[k % len(pool)]`

- **결정**: pool 은 템플릿 번호순(기본 20개, `skip_slide` 는 1-based로 제외). 배경과 스타일을 같은 슬라이드에서 함께 가져온다.
- **근거**: 수식 하나로 20 미만/초과/정확히 20 을 모두 처리하고, wrap-around 가 자동이다.
- **결과**: 경계 동작 표(`04 §2.2`) 전부 확정. 0줄은 `EmptyLyricsError`, pool 비면 `ConfigError`.
- **관련**: 계획 D7, R5 / `04 §2`.

## AD-11. slide1 빈 텍스트 대응 — 스타일 폴백

- **결정**: `template_reader` 가 슬라이드별 `shape_found`/`has_rpr` 를 기록. `rPr` 이 없으면 `default_style`
  (run 을 가진 첫 슬라이드, 실측 slide2)로 폴백하고 WARNING 1회.
- **맥락**: slide1 은 run 이 0개다. `제목 1` 도형이 없을 가능성이 있다.
- **근거**: 풀에서 slide1 을 제외하면 배경 20종 중 1종을 잃는다(계획 Q2 기본: 포함). 폴백이 더 낫다.
- **결과**: slide1 배경도 사용 가능. T04 에서 실제 도형 유무를 확정하고, 없으면 이 폴백이 동작.
- **관련**: `04 §1`, `04 §4.2`.

## AD-12. 원본 20장 제거 — 참조만 제거, 파트는 보존

- **결정**: `sldIdLst` 에서 원본 `sldId` 를 모두 제거하고 복제본만 재등록. 파트 삭제는 하지 않는다.
- **근거**: media/layout/theme 파트를 지우면 배경이 죽는다(R7). 참조만 제거하면 산출물에 원본 슬라이드가 안 보이고
  파트는 살아남는다.
- **결과**: `len(sldIdLst) == N`, `Presentation(out)` 재열기 성공이 완료 조건.
- **관련**: `04 §3.5`, R7.

## AD-13. 원자적 쓰기 — `output/.tmp-<uuid>.pptx` → `os.replace`

- **결정**: 같은 볼륨 tmp 에 저장 → 재열기 검증 → `os.replace`. 실패 시 tmp 삭제.
- **근거**: 저장 중 실패하면 반쪽 pptx 가 최종 이름을 차지해 사용자가 손상 파일을 연다. 검증 후 교체로 차단.
- **결과**: 기존 파일은 성공 시에만 덮어씀. `.tmp-*` 는 `.gitignore` 대상.
- **관련**: `08 §4`.

## AD-14. 빌드 직렬화 (전역 락)

- **결정**: 웹서버가 스레드 기반이라도 pptx 빌드는 프로세스 전역 `threading.Lock` 으로 직렬화.
- **근거**: 빌드 1건이 37MB 템플릿을 열어 메모리에 올린다. 병렬 빌드는 메모리·파일 잠금 위험만 늘린다.
- **결과**: 동시 요청은 큐잉(대기). 단순성 유지, 큐 시스템 불필요.
- **관련**: `01 §3`, `08 §6`.

## AD-15. 웹서버 보안 경계 — localhost 바인딩 + 정적 containment + 요청 상한

- **결정**: 기본 `127.0.0.1:8765`. `/static/*` 는 해결 경로가 `web/` 하위인지 검사. 요청 본문 1 MiB 상한.
- **근거**: 단일 사용자 로컬 도구지만, 경로 탈출·대용량 요청은 "단순함"과 무관하게 막아야 하는 최소 비용 방어다.
- **결과**: 사용자 인증·레이트리밋은 미채택(인증 대상 없음). 상태 변경 엔드포인트가 생긴 뒤의 최소 가드는 AD-17 로 분리한다.
- **관련**: `06 §3`, `06 §6`.

## AD-16. 로깅 = 표준 `logging`, 루트 `lyrics2pptx`, stderr, INFO

- **결정**: 포맷 `%(asctime)s %(levelname)s %(name)s %(message)s`, stderr, 진입점에서 1회 초기화.
  가사 본문은 DEBUG 만 + 60자 truncate.
- **근거**: 외부 관측 스택을 도입할 대상이 아니다(단일 프로세스). stdout 은 `--json` 데이터 전용으로 남겨 파이프 안전성 확보.
- **결과**: 메트릭/트레이싱 미채택. 요청 로그는 `rid` LoggerAdapter 로 상관관계 부여.
- **관련**: `07 §1–5`.

## AD-17. 세션 수명과 상태 변경 가드 — 탭 3분 · 무활동 20분 · 최대 3시간 (ADR-032)

- **결정**: 서버가 **스스로 종료**한다(탭 닫힘 비콘 3분 · 무활동 20분 · 최대 3시간, 진행 중 작업은 보류). 상태를 바꾸는 요청
  (`/api/shutdown`·`/api/reveal`·탭 닫힘 비콘)은 `GET /` 에만 심는 **1회 토큰 + `Origin`** 검사를 통과해야 한다.
  런처는 `output\webui.state` 의 `instance` 를 `/api/ping` 응답과 비교해 **살아 있는 서버를 재사용**한다(중복 기동 방지).
- **근거**: AD-15 는 "상태 변경이 없다"를 전제로 CSRF 를 생략했지만, 종료·탐색기 열기가 생기면서 그 전제가 깨졌다.
  포트가 추측 가능한 루프백 서버라 토큰이 없으면 아무 웹사이트나 사용자의 서버를 죽일 수 있다.
  수명 규칙은 편의 기능이 아니라 **불안 제거 UX**다 — "끄는 법을 가르치는 대신 끌 필요를 없앤다".
- **결과**: AD-15 의 "인증/CSRF 미채택" 서술은 이 항목으로 대체된다(사용자 인증은 여전히 없다). 탭 신호 단독에 의존하지 않고
  무활동·최대 수명을 안전망으로 함께 둔다. `/api/ping` 이 heartbeat·비콘·상태 조회를 겸하는 단일 계약이 된다.
- **관련**: `05 §2.5·§6`, `06 §3·§7`, `ADR-032`(결정문서), AD-15.

## AD-18. 패키징 — 얼린 exe 하나 + 동봉 3종, 경로는 `sys.frozen` 하나로 갈린다 (ADR-033)

- **결정**: PyInstaller `--onefile --noconsole` 로 `lyrics2pptx.exe` 하나를 만들고, `template.pptx`·`사용법.txt` 와 함께 zip 으로 묶는다.
  얼린 실행에서는 `ROOT = exe 폴더`(사용자가 읽고 쓰는 곳 — 템플릿·`output/`)이고 `web/` 은 `sys._MEIPASS`(번들 내부)에서 읽는다.
  진입은 `webapp.launch()` 하나 — 실행 중인 서버가 있으면 그 탭만 열고, 없으면 서버를 띄우고 탭을 열며, 로그는 `output\launch.log` 에 append 한다.
- **근거**: "설치 없이 더블클릭" 요구는 개발자 경로(`python -m …`, `.vbs`)로 만족할 수 없다. 반대로 얼린 앱은 콘솔이 없어
  **증거가 사라지므로** 로그 파일이 신고 경로의 최소 조건이 된다(G7). 경로를 한 곳에서만 분기하면 개발 트리·CI 는 그대로 유지된다.
- **결과**: 배포는 zip 하나(67.5MB), 사용자 절차는 세 동작. `.vbs` 는 개발자용으로 남고 같은 상태 파일 규칙(AD-17)을 공유한다.
  onefile 은 프로세스가 2개 보이는 것이 정상이며, 끄는 절차는 여전히 AD-17 이 담당한다.
- **관련**: `02 §2`(계층 밖 빌드 도구), `05 §6`(실행·종료 계약), `06 §3`(보안 경계는 그대로), `ADR-033`(결정문서), AD-17.

## AD-19. 템플릿 교체 지원 — 도형 자동 인식 · 서식 합성 · 단색 배경 썸네일 (ADR-034)

- **결정**: 가사 도형을 ① 이름(env/인자) → ② `제목 1` → ③ **추정**(글자 있는·전면 아님·그림 아님 → 면적 큰 순) 순으로 찾는다.
  선택 슬라이드에 `a:rPr` 이 없으면 상자 높이×0.42(18~66pt)·검정·맑은 고딕으로 **합성**하고, 그림 배경이 없으면
  `a:srgbClr` 로 640px PNG 썸네일을 그린다. 기본 배경 번호가 템플릿 범위를 넘으면 마지막 슬라이드로 가되(명시값은 하드 오류),
  `--doctor` 와 로그가 무엇을 골랐는지 말한다.
- **근거**: "PPT 만 바꾸면 된다"는 요구는 이름·서식 규칙을 문서로 읽히게 해서 만족되지 않는다(ADR-033 계약은 `제목 1`+`rPr` 필수라
  교체 시 exit 4). 반대로 조용히 넘어가면 안 되므로 추정·합성은 WARNING 과 `--doctor` 로 드러낸다.
- **결과**: 4장 4:3 교체 템플릿(이름 다름·서식 없음·단색 배경)으로 exe 종단 실측 통과(생성 3/3, 썸네일 3/3, 미리보기 200).
  동봉 템플릿은 동작 불변(66pt·좌표 동일, 경고 0). 576 tests.
- **한계**: 테마/마스터 배경, 스마트아트·표 안 텍스트는 다루지 않는다. 추정은 틀릴 수 있어 `제목 1` 이름 지정이 최종 수단이다.
- **관련**: `02 §2`, `05 §6`, `ADR-034`(결정문서), AD-18(패키징).

## AD-20. 템플릿 교체의 남은 한계 5종 — 배경 상속 · 테마 색 · 전면 허용오차 · 도형 점수화 · 그룹 좌표 (ADR-035)

- **결정**: ① 배경을 **슬라이드 → 레이아웃 → 마스터** 순으로 상속 해석하고, ② `schemeClr`/`sysClr`/`prstClr`
  (+`tint`/`shade`/`lumMod`/`lumOff`/`alpha`)을 실제 RGB 로 푼다. ③ 전면(배경) 판정은 각 변 **1%(≥1270 EMU)** 허용,
  ④ 가사 도형은 점수로 고른다 — 제목 placeholder +100 · 이름에 `가사`/`lyrics` +80 · `제목`/`title` +60 · 글자 있음 +25 ·
  면적 최대 +30, `sldNum`/`dt`/`ftr` placeholder 제외. ⑤ `p:grpSp` 안의 도형은 그룹 변환을 되돌려 **슬라이드 좌표**로 환산하고,
  서식이 없을 때 합성하는 글자는 배경 명도 0.45 미만이면 **흰색**, 글꼴은 테마의 동아시아 글꼴(없으면 맑은 고딕)을 쓴다.
  글자가 표/스마트아트 안에만 있으면 "표·스마트아트는 지원하지 않습니다" 전용 문구로 실패한다.
- **근거**: ADR-034 이후에도 ① 마스터에 배경을 둔 PPT → 흰 칸, ② 테마 색 배경 → 흰 칸, ③ 손으로 그린 배경 사각형 →
  가사가 배경 안으로, ④ 표지/간지처럼 상자가 여럿인 슬라이드 → 엉뚱한 상자, ⑤ 그룹 안 글상자 → 크기·순위 오판이 남아 있었다.
