# 08. 로드맵과 리스크 (Roadmap and Risks)

이 문서는 실행 순서, 의존 그래프, 리스크, 최종 인수를 담는다.
각 태스크의 상세 "done when"은 해당 관심사 문서(02~07)에 있다.

## 1. 의존 그래프

```
T01 스캐폴딩
 ├── T02 정규화 ── T03 분할 ─────────────┐
 ├── T04 복제 ── T05 채우기 ── T06 빌더 ─┤
 └── T07 수집 인터페이스 ── T08 어댑터 ───┤
                                          ├── T09 CLI ──┐
                                          └── T10 웹앱 ─┤
                                                        └── T12 인수
                       T02,T06 ── T11 테스트 정리 ────────┘
```

병렬 가능 구간: `{T02,T03}` / `{T04,T05}` / `{T07,T08}` 는 T01 이후 서로 독립.
합류 지점: T06(빌더) 와 T08(어댑터) 가 끝나야 T09/T10 이 가능하다.

## 4. 리스크와 대응

| # | 리스크 | 영향 | 대응 |
| --- | --- | --- | --- |
| R1 | python-pptx 내부 API로 슬라이드 파트 등록이 버전에 따라 불가 | 치명(핵심 기능) | 05 §7 폴백: `zipfile`+`lxml` 로 패키지 직접 재작성. T04를 최우선 실행 |
| R2 | rels 재매핑 실수로 배경 그림 누락 | 높음 | `test_clone.py` 로 rel 존재·대상 검증, 전면 `<p:pic>` 슬라이드 필수 테스트 |
| R3 | 가사 소스 미확정/차단 | 중 | 어댑터 분리 + 직접 입력 경로 1급 지원(03). 수집 실패가 pptx 기능을 막지 않음 |
| R4 | 한국어 가사 커버리지 부족(기본 API) | 중 | 사용자 확인 후 전용 어댑터 교체 지점 제공. 미해결로 남겨도 파이프라인은 동작 |
| R5 | 긴 가사 줄이 2줄을 초과 | 중 | `normAutofit` 로 렌더러가 축소. 사용자가 "폰트 고정"을 원하면 재검토(D8) |
| R6 | 템플릿 `제목 1` 이 없는 슬라이드가 섞임 | 낮음 | 이미 20장 전부 존재 확인. 새 템플릿 교체 시 `TemplateStructureError` 로 조기 실패 |
| R7 | 원본 20장 제거 로직이 테마/media 를 훼손 | 중 | 파트 삭제가 아니라 `sldIdLst` 참조만 제거, 재열기 테스트로 무결성 확인 |
| R8 | 노트 복제 여부에 대한 사용자 이견 | 낮음 | 기본 미복제(D9). `keep_notes` 플래그로 전환 가능하게 구현 |

## 6. 최종 인수 (End-to-End, T12)

1. `python -m pip install -r requirements.txt` 성공
2. `python -m lyrics2pptx.webapp` → 브라우저에서 검색어 입력 → 결과 선택 → 생성 → 다운로드
3. 다운로드한 pptx 를 PowerPoint 로 열기: 2줄씩 표시, 배경 순환, 원본 20장 부재, 노트 빈 상태
4. `python -m unittest discover -s tests -v` 전체 통과(네트워크 차단 상태)

위 4개가 모두 성립하면 프로젝트 완료다.
