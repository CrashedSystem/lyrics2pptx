# 01. 목표와 범위 (Goals and Scope)

이 문서는 `계획서.md`의 "요약 / 확정 제약"이 구현에서 무엇을 의미하는지 고정한다.
하위 문서 02~08의 모든 결정은 이 문서의 비목표(non-goals)를 위반할 수 없다.

## 목표 (Goals)

| # | 목표 | 검증 신호 |
| --- | --- | --- |
| G1 | 검색어 하나(예: 곡 제목)로 가사를 수집한다 | T08: 실제 검색어 1건에 대해 `RawSong` 반환 |
| G2 | 수집 결과를 정규화해 "줄" 단위 텍스트로 만든다 | T02: 정규화 테스트 통과 |
| G3 | 줄을 **2줄씩** 묶어 슬라이드 단위로 분할한다 | T03: 짝수/홀수 케이스 통과 |
| G4 | `template.pptx`의 슬라이드를 복제해 배경을 그대로 유지한다 | T04: 배경 그림 rels 유지 |
| G5 | 복제 슬라이드의 `제목 1` 도형에 2줄을 채운다 | T05: 텍스트 2줄 + 서식 유지 |
| G6 | 결과를 `.pptx` 파일로 내려받는다 | T09/T10: 파일 생성 및 다운로드 |
| G7 | 배경 20종을 순환 사용하고 20장 초과 시 wrap-around 한다 | T06: 25줄 → 13장, 배경 순서 검증 |

## 비목표 (Non-goals) — 넣지 않은 것과 이유 (한 줄씩)

| 제외 항목 | 이유 (한 줄) |
| --- | --- |
| 데이터베이스 | 입력이 검색어 1개이고 저장 대상이 산출 pptx 파일뿐이라 파일 시스템이 곧 저장소다. |
| 사용자 인증 / 계정 | localhost 단일 사용자 도구라 인증 대상이 없다. |
| 세션·상태관리 라이브러리 | 화면 입력 필드가 3개뿐이라 브라우저 메모리로 충분하다. |
| 프론트엔드 프레임워크(React 등)·컴포넌트 라이브러리 | 정적 1페이지 + `fetch` 호출 2개면 끝나는 UI다. |
| Flask/FastAPI 등 웹 프레임워크 | 라우트가 3개(`GET /`, `GET /api/search`, `POST /api/generate`)라 표준 `http.server`로 충분하다. |
| 비동기 큐/워커/캐시 서버 | 요청 1건당 처리 수 초, 동시 사용자 1명이라 직렬 처리로 충분하다. |
| 다국어 가사 번역·음차 | 원문 그대로가 요구사항이고 번역 품질 책임을 질 수 없다. |
| 후렴 자동 제거(기본값) | 원문 충실성이 우선이며, 자동 제거는 정보 손실 위험이 있다(옵션으로만). |
| 가사 편집 GUI(줄 단위 수정) | "단순함" 제약과 충돌. 재생성으로 대체한다. |
| 클라우드 배포/도커 | 로컬 실행이 요구사항이다. |
| 템플릿 디자인 생성 | 사용자가 이미 `template.pptx`를 제공했다. |
| notesSlide(발표자 노트) 생성 | 템플릿 노트는 원곡 전용 내용이라 복제하면 오히려 오염된다(05 참조). |
| 폰트 임베딩/폰트 교체 | 템플릿 폰트를 유지하는 것이 요구사항이다. |

## 확정 설계 결정 (Decision Log)

각 결정의 상세 근거는 해당 문서에 있다. 여기서는 결정과 한 줄 근거만 고정한다.

| # | 쟁점 | 결정 | 근거 (한 줄) | 상세 |
| --- | --- | --- | --- | --- |
| D1 | 수집 소스 | 소스를 코드에 하드코딩하지 않고 `Source` 어댑터 인터페이스로 분리. 기본 제공은 키 없는 공개 API 1종 + 사용자가 지정한 사이트용 HTML 어댑터 스켈레톤 | 어느 사이트인지 확정 불가하고, 사이트별 약관·차단 정책이 바뀌므로 교체 지점을 분리해야 지속 가능하다 | 03 |
| D2 | 법적 리스크 | HTML 스크래핑은 robots.txt 확인 + 요청 간 지연 + UA 명시를 강제하고, 이용약관 위반 소지가 있는 소스는 기본값에서 제외 | 합법·지속 가능한 소스만 기본 경로로 두고, 위험 소스는 사용자 선택으로 남긴다 | 03 |
| D3 | 텍스트 정규화 | 개행 통일 → 공백 정리 → 섹션마커/빈 줄 제거 → 줄 배열화의 고정 파이프라인 | 결정적(deterministic) 순서가 있어야 테스트가 가능하다 | 04 |
| D4 | "2줄씩" 정의 | 정규화 후 **비어 있지 않은 줄**을 순서대로 2개씩 묶음. 홀수면 마지막 슬라이드는 1줄 | "줄"의 정의가 흔들리면 산출 슬라이드 수가 흔들린다 | 04 |
| D5 | 후렴 반복 | 기본은 그대로 유지(중복 제거 안 함) | 원문 충실. 옵션 플래그로만 제거 허용 | 04 |
| D6 | pptx 생성 | `template.pptx`를 열고 소스 슬라이드 XML을 `copy.deepcopy` 후 rels(`r:embed`/`r:id`)를 재매핑해 복제한 뒤 텍스트만 교체 | python-pptx에 슬라이드 복제 API가 없어 XML 수준 복제가 유일한 길이고, "내용만 채우기" 요구에 정확히 맞는다 | 05 |
| D7 | 배경 순환 | 배경 풀 = template 슬라이드 20장(번호 순). n번째 출력 슬라이드는 `template[n % 20]` 배경 | 20종을 다 쓰고 초과분은 자연 순환시켜 규칙을 단순하게 유지 | 05 |
| D8 | 폰트/사이즈 | run 서식을 템플릿에서 상속(첫 run의 `rPr` 복제), 크기 고정 + `normAutofit`만 켜서 넘칠 때 PowerPoint가 축소 | 우리가 텍스트 픽셀 폭을 정확히 측정할 수 없으므로 렌더러에 위임하는 편이 안전 | 05 |
| D9 | notesSlide | 복제하지 않음(새 슬라이드에 노트 rel 없음) | 템플릿 노트는 원곡 전용이라 복제하면 잘못된 내용이 붙는다 | 05 |
| D10 | 전달 형태 | 웹 UI 채택. 단 CLI도 유지 | 사용자가 웹 앱을 선택했고, 검색→미리보기→다운로드 흐름은 브라우저가 자연스럽다. CLI는 자동화·테스트에 필요 | 06 |
| D11 | 테스트 | 표준 `unittest` + 오프라인 fixture(저장된 응답) | 네트워크 없이 결정적으로 검증해야 크롤링이 테스트 가능해진다 | 07 |

## 성공의 정의 (Definition of Done, 프로젝트 전체)

1. `python -m lyrics2pptx.webapp` 실행 후 브라우저에서 검색어 입력 → 결과 pptx 다운로드가 된다.
2. 산출 pptx를 PowerPoint에서 열면 각 슬라이드에 가사 2줄이 `제목 1` 위치에 표시된다.
3. 배경이 슬라이드마다 다르고, 슬라이드 수가 20을 넘으면 배경이 처음부터 다시 순환한다.
4. `python -m unittest discover -s tests` 가 네트워크 없이 통과한다.
