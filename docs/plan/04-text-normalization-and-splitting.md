# 04. 텍스트 정규화와 2줄 분할 (Normalization and Splitting)

담당 태스크: **T02** (정규화), **T03** (2줄 분할)

## 1. 정규화 파이프라인 (`text/normalize.py`)

입력: `RawSong.lyrics` (원문, 소스마다 제각각)
출력: `list[str]` — 비어 있지 않은 "줄"의 순서 있는 배열

단계는 **고정 순서**다. 순서가 바뀌면 결과가 달라지므로 테스트로 고정한다.

| 순서 | 단계 | 규칙 |
| --- | --- | --- |
| N1 | 개행 통일 | `\r\n`, `\r` → `\n` |
| N2 | 유니코드 정규화 | NFC (`unicodedata.normalize("NFC", s)`) — 한글 자모 분리 방지 |
| N3 | 제로폭/특수공백 | `\u200b`, `\ufeff` 제거, NBSP(`\u00a0`) → 일반 공백 |
| N4 | 줄 단위 분해 | `s.split("\n")` |
| N5 | 줄별 공백 정리 | 앞뒤 공백 제거, 2개 이상 연속 공백 → 1개 (`re.sub(r"[ \t]+", " ", line)`) |
| N6 | 섹션 마커 제거 | 줄 **전체**가 마커일 때만 삭제 — 키워드 단독이거나 키워드 + 숫자 중심 접미(`Verse 1`, `chorus x2`, `후렴 2절`, `[Chorus]`) |
| N7 | 빈 줄 삭제 | 공백만 있는 줄(빈 문자열) 삭제 |
| N8 | 중복 연속 줄 정리 | 완전히 동일한 줄이 **연속 3회 이상** 반복되면 1회로 축소 (2회는 유지) |
| N9 | 트레일링 마커 제거 | 줄 끝의 `|`, `-`, `~` 반복 제거 |
| N10 | 결과 | `list[str]` |

### N6 상세 (섹션 마커)

삭제 조건(구현): 줄을 `^\s*[\[\(（]?(?P<inner>[^\]\)）]{0,12})[\]\)）]?\s*$` 로 감싼 대괄호/공백 장식을
벗긴 뒤, **잔여 텍스트 전체**가 다음 중 하나일 때만 삭제한다. **부분 문자열(contains) 매칭이 아니다.**

- **키워드 단독**: `verse`, `chorus`, `bridge`, `intro`, `outro`, `후렴`, `절`, `간주`, `x2`, `×2`, `※`
- 또는 키워드 + **숫자 중심 접미** `[ :]*[x×]?[0-9]*절?` → `Verse 1`, `verse2`, `chorus x2`, `후렴 2절`, `Chorus:`
- 대괄호 장식 인정: `[Chorus]`, `(후렴)`

| 입력 | 결과 |
| --- | --- |
| `Verse 1`, `verse 1`, `chorus x2`, `후렴 2절`, `[Chorus]`, `(후렴)`, `※`, `×2` | **삭제**(마커) |
| `chorus line`, `intro to me`, `outro music` | **보존**(뒤에 임의 단어 → 실제 가사) |
| `절망마저`, `이 간주곡` | **보존**(`절`/`간주` 로 시작해도 접미가 숫자 규칙 위반) |

> **fail-safe: 확신이 없으면 지우지 않는다(보존).** 키워드로 시작해도 뒤에 임의의 단어가 오면
> 실제 가사 줄로 보고 남긴다. (정정: 이전 판은 "포함(contains)" 으로 서술했으나 구현은
> **전체 일치 + 숫자 중심 접미**다 — `src/lyrics2pptx/text/normalize.py::_is_section_marker`.)

### 대표 예시

원문(fixture `lyrics_sample.txt`):

```
[Verse 1]
너는 담장 너머로\r\n
 붉은  나무가지에   푸른 열매처럼


우리 함께 손잡고 가세
조금 느리고 어려울지라도
(×2)
```

정규화 결과:

```python
[
  "너는 담장 너머로",
  "붉은 나무가지에 푸른 열매처럼",
  "우리 함께 손잡고 가세",
  "조금 느리고 어려울지라도",
]
```

(N6이 `[Verse 1]`과 `(×2)`를 제거, N7이 빈 줄 제거, N5가 다중 공백 병합)

## 2. 2줄 분할 (`text/split.py`)

**정의 (D4)**: 정규화된 줄 배열을 **순서대로 2개씩** 묶는다.
"줄" = N10의 배열 원소. 빈 줄은 이미 존재하지 않는다.

```python
from __future__ import annotations

LinePair = tuple[str, str | None]

def split_pairs(lines: list[str]) -> list[LinePair]:
    """2줄씩 묶는다. 홀수면 마지막 페어의 둘째 줄은 None."""
    return [
        (lines[i], lines[i + 1] if i + 1 < len(lines) else None)
        for i in range(0, len(lines), 2)
    ]
```

### 규칙 표

| 상황 | 처리 | 근거 |
| --- | --- | --- |
| 짝수 개 줄 | 정확히 `n/2` 페어 | 자명 |
| 홀수 개 줄 | 마지막 페어 = `(마지막줄, None)` → 슬라이드에 1줄만 | 빈 슬라이드 방지, 정보 손실 없음 |
| 빈 줄 | N7에서 이미 제거 → 페어 수에 영향 없음 | "빈 줄이 슬라이드를 먹는" 문제 차단 |
| 줄이 0개 | 페어 0개 → **빌더가 오류**: `EmptyLyricsError` | 빈 pptx 생성 방지 |
| 줄이 1개 | 페어 1개 = `(줄, None)` | 최소 1장 보장 |
| 원문의 짧은 호흡 줄(빈 줄로 나뉜 구절) | 빈 줄은 사라지지만 **줄 순서는 유지** | 사용자는 "2줄"만 원하고 구절 경계는 요구하지 않음 |

### 후렴 반복 (D5)

- 기본: **중복 제거 안 함**. 원문 그대로 페어링.
- 옵션: `split_pairs(lines, dedupe_repeat=False)` — `True`면 완전히 동일한 줄이 3회 이상 나올 때 첫 (2의 배수)개만 유지. CLI `--dedupe-chorus` / 웹 UI 체크박스는 **기본 꺼짐**.
- N8과의 관계: N8은 "연속 3회 이상"만 축소하는 안전장치, `dedupe_repeat`는 "떨어져 있는 후렴"까지 건드리는 별개 옵션.

### 한글/영문 혼용

- 번역·음차·대소문자 변환 없음. N2의 NFC만 적용.
- 공백 정리는 한글/영문 동일 규칙(2+ 공백 → 1).
- 영문 줄은 절대 단어 단위로 쪼개지 않는다(한 줄 = 한 줄).

## 3. 데이터 흐름

```
RawSong.lyrics (str)
  → normalize_lines() → list[str]
  → split_pairs()     → list[LinePair]   # 길이 = ceil(줄수 / 2) = 출력 슬라이드 수
  → builder.build(pairs) → .pptx
```

## 4. 실패/엣지 케이스

| 케이스 | 결과 |
| --- | --- |
| 정규화 후 줄 0개 | `EmptyLyricsError("가사에서 유효한 줄을 찾지 못했습니다.")` |
| 줄 전체가 섹션 마커 | 위와 동일 |
| 매우 긴 한 줄 | 자르지 않음. 폰트 축소는 pptx 단계(05)가 담당 |
| 줄 끝 콤마/마침표 혼재 | 유지 (정규화 대상 아님) |
| 전각/반각 혼용 | 유지 (NFC가 호환 변환을 하지 않음) |
