# 사용 가이드 — 실제 시나리오로 보는 lyrics2pptx

이 문서는 "설치 후 실제로 어떻게 쓰는가"만 다룬다. 명령/옵션 전체는 `README.md`, 구조는
`아키텍처.md` 를 참고한다. 여기 적힌 동작 규칙은 모두 `src/lyrics2pptx` 코드에서 확인한 것이다.

---

## 1. 시나리오 A — 검색해서 만들기

```powershell
python -m lyrics2pptx.cli --query "아티스트 - 곡명" -o "output\곡명.pptx"
```

1. `"아티스트 - 곡명"` 형태면 그 한 건을 바로 찾고, 곡명만 주면 소스의 검색(suggest) API 로
   후보를 모은다(순차 요청, 요청 사이 지연 적용).
2. 결과는 **`--index`** 로 고른다(기본 0). 후보를 먼저 보고 싶으면:

   ```powershell
   python -m lyrics2pptx.cli --query "곡명" --json     # stdout 에 후보 목록(JSON)
   python -m lyrics2pptx.cli --query "곡명" --index 2  # 3번째 후보로 빌드
   ```

3. 성공하면 stdout 에 최종 경로 한 줄만 출력되고 exit 0.

**기본 소스는 `auto`** — 먼저 `lrclib.net`(키 없는 공개 API, 한국 워십/CCM 다수)을 묻고, 없으면
**블로그 검색 + 다수결 교차검증**(`blog`)으로 폴백한다(ADR-018). `lrclib` 은 literal substring
검색이라 `생명샘` 처럼 DB에 없는 곡은 못 찾는다 — 그때 `auto` 가 웹에서 찾아 준다.
검색 결과가 없으면 exit 1(메시지: 가수로 검색하거나 직접 붙여넣기 안내)로 끝난다.

### 1.1 합의 가사가 맞는지 확인하기 (`--cross-check`)

여러 페이지가 같은 곡을 조금씩 다르게 필사한다(`에스길`↔`에스겔`, `환란 날이`↔`환난날이`).
합의 가사(다수결)만 믿지 말고 **근거를 먼저 확인**한다:

```powershell
python -m lyrics2pptx.cli --query "곡명" --cross-check
```

출력 예(요약): 각 줄에 `지지수/전체수` 와 **다른 표기**가 붙는다.

```
# 지금은 엘리야 때처럼 (4곳 교차검증, 24줄)
 12. 에스겔의 환상처럼   [2/4]   다른 표기: 에스길의 환상처럼
 18. 우리는 추수할 일꾼되어   [2/4]   다른 표기: 우리는 추수할 일꾼 되어
# 불일치 15줄 / 전체 24줄
```

- `[2/4]` = 4페이지 중 2페이지가 이 표기를 썼다는 뜻. **2-2 동률**은 줄 모양이 더 흔한 쪽(medoid)으로
  정해지므로, 다른 표기가 맞다고 판단되면 그 페이지를 직접 고른다:
  `python -m lyrics2pptx.cli --query "곡명" --source blog --index 1` (0=합의, 1~=개별 페이지).
- `--cross-check` 는 **파일을 만들지 않는다**. 확인 후 `--source blog --index 0`(합의) 또는
  다른 `--index` 로 빌드한다.
- 웹 수집은 페이지당 지연(기본 2초)을 지켜 느리고, 가사를 **이미지로만** 올린 페이지는 건너뛴다.
  `LYRICS2PPTX_BLOG_MAX_PAGES`(기본 5)로 상한을 낮출 수 있다.

**"교차검증 안 됨" 이 보이면 후보를 직접 고른다 (ADR-020).** 실제로 투표한 페이지가 2장 미만이면
도구는 합의를 주장하지 않는다:

```
# 정금같이 나오리라 — 교차검증 안 됨 (후보 2개), 47줄
# 경고: 후보 2개가 서로 다른 곡입니다. 아래 줄은 한 페이지의 필사본이므로 직접 확인하세요.
```

이때는 `--cross-check` 대신 후보 목록을 본다. 각 후보는 `호스트 · N줄` 로 표시되므로 어느 페이지가
어떤 곡인지 구분해 고른다(`--source blog --index N`). 성경 구절 페이지·다른 곡 목록 페이지·동명이곡은
후보에서 걸러지거나 이 라벨로 드러난다("조용히 한 페이지를 고르지 않는다").

**투표에서 빠진 페이지는 `(투표 제외)` 로 표시된다 (ADR-021).** 일관성 검사가 "이 페이지는 같은 곡이
아니다"(다른 곡, 가사가 이미지인 페이지의 사이드바 안내문 등)라고 판단해 투표에서 제외한 페이지다.
보고 싶으면 고를 수 있지만, **투표에 참여한 페이지가 아니라는 사실이 라벨에 적혀 있고 목록 뒤로 밀린다.**
예: `gvctranslation.tistory.com · 6줄 (투표 제외)`. 참고로 사이트 자체 카운터가 붙은 줄
(`메일로 (0)`, `어린이찬송가 (478)`)은 가사로 읽지 않는다.

> 실행 중 소스가 403/404 를 주면 차단(exit 2), 429/5xx/타임아웃은 지수 백오프(1·2·4초,
> `LYRICS2PPTX_MAX_RETRIES` 회)로 재시도 후 실패(exit 2)한다.

> **검증 상태**: `--query` 의 실 네트워크 호출은 **검증됐다** — `lrclib.net`(어노인팅 → 후보 반환,
> `생명샘` → 0건) 과 `auto`/`blog` 폴백(`지금은 엘리야 때처럼` → 4페이지 합의 24줄, ADR-018).
> 오프라인에서 파이프라인 자체를 확인하려면 fixture 모드를 쓴다(exit 0, 검증됨):
> `$env:LYRICS2PPTX_FIXTURE_DIR="tests\fixtures"; python -m lyrics2pptx.cli --query "생명샘"`.

### 1.2 웹 UI 로 할 때 — 화면 하단 "진행 카드"

```powershell
python -m lyrics2pptx.webapp        # 또는 webui.cmd  → http://127.0.0.1:8765
```

검색은 블로그 페이지를 여러 장 받아오느라 오래 걸리므로, 검색/생성 중에는 화면 하단에
**진행 카드**가 고정된다(ADR-019).

- **단계 목록**: 지금 무엇을 하는지. 끝난 단계는 체크(✓), 현재 단계는 맥동하는 점.
  `3/5 lyrics.co.kr 페이지 확인 중…` = "확인할 페이지 5장 중 3장째".
- **경과 시간**: `12.4초` 처럼 계속 올라간다 → 멈춘 게 아니라는 신호.
- **진행 막대**: 페이지 수처럼 **총량을 아는 단계만** 채워진다. 총량을 모르는 단계
  (`lrclib 소스 조회 중…`, 교차검증)에서는 숫자를 지어내지 않고 **흐르는 막대**로 표시한다.
- 끝나면 카드가 초록으로 가득 찬 뒤 1.2초 후 사라진다.

> 진행 카드는 "얼마나 남았는가"가 아니라 **"지금 무엇을 하고 있는가"** 를 알려 준다.
> 남은 시간은 페이지 응답 속도에 달려 있어 예측하지 않는다(예측이 틀리면 신뢰를 잃는다).

검색이 길어질 때 조정할 것: `LYRICS2PPTX_BLOG_MAX_PAGES`(기본 5)를 낮추면 페이지 수가 줄어
빨라진다(대신 교차검증 표본이 줄어든다). 웹 UI 는 검색 버튼이 눌린 동안 비활성화되며
**취소는 없다** — 창을 닫아도 서버 작업은 끝까지 돈다(로컬 단일 사용자용).

## 2. 시나리오 B — 가사 붙여넣어 만들기 (한국어 권장)

```powershell
python -m lyrics2pptx.cli --input-file "가사.txt"       # 정규화(N1~N11) 적용
python -m lyrics2pptx.cli --lines-file "lines.txt"      # 이미 정리된 줄, 정규화 생략
```

- `--input-file`: 원문을 그대로 넣으면 된다. 빈 줄·`[Verse]` 같은 표시·중복 공백·줄끝 기호를
  자동 정리한다.
- `--lines-file`: **한 줄에 한 문장**씩 이미 정리된 파일. 정규화를 건너뛰고 공백 트림/빈 줄 제거만 한다.
- 웹 UI 의 **"직접 입력"** 모드도 같다. 붙여넣으면 250ms 디바운스 후 서버가 미리보기를 계산한다.

두 입력 모두 **네트워크를 전혀 쓰지 않는다**. 저작권이 걱정되거나 소스가 막힌 상황의 대안이다.

## 3. "2줄 분할" 규칙은 이렇게 동작한다

### 3.1 줄 정리 (N1~N11, `text/normalize.py`)

| 단계 | 하는 일 |
| --- | --- |
| N1 | 개행 통일: `\r\n`, `\r` → `\n` |
| N2 | 유니코드 NFC 정규화 (한글 자모 결합) |
| N3 | 제로폭(BOM/ZWSP 등) 제거, NBSP → 일반 공백 |
| N4 | 줄 단위 분해 |
| N5 | 줄별 앞뒤 공백 제거, 2칸 이상 연속 공백 → 1칸 |
| N6 | **섹션 마커 전용 줄 삭제**(아래 3.2) |
| N7 | 빈 줄(공백만) 삭제 |
| N8 | 완전히 같은 줄이 **연속 3회 이상**이면 1회로 축약 (2회는 유지) |
| N9 | 줄 끝의 `|`, `-`, `~` 반복 제거 |
| N11 | **추임새(애드립) 제거** — 아래 3.3 |
| N10 | 남은 줄을 순서대로 누적 |


### 3.2 N6 — 무엇이 마커이고 무엇이 실제 가사인가

**규칙: 줄 전체(앞뒤 대괄호/공백 제거 후)가 마커일 때만 지운다.** 부분 문자열 매칭이 아니다.

- 마커 키워드: `verse`, `chorus`, `bridge`, `intro`, `outro`, `후렴`, `절`, `간주`, `x2`, `×2`, `※`.
- 키워드 뒤에는 **숫자 중심 접미**만 허용: 공백/콜론 + 선택적 `x`/`×` + 숫자 + 선택적 `절`.
- 대괄호 장식(`[Chorus]`, `(후렴)`)과 `※` 도 인정.

| 입력 | 결과 | 이유 |
| --- | --- | --- |
| `[Verse 1]` | **삭제** | 키워드 + 숫자 접미 |
| `verse 1` | **삭제** | 동일 |
| `chorus x2` | **삭제** | `x` + 숫자 접미 |
| `후렴 2절` | **삭제** | 한글 키워드 + 숫자 + `절` |
| `[Chorus]` | **삭제** | 대괄호 장식 |
| `(후렴)` | **삭제** | 대괄호 장식 |
| `※` | **삭제** | 키워드 단독 |
| `×2` | **삭제** | 키워드 단독 |
| `chorus line` | **보존** | 뒤에 임의 단어 → 실제 가사 |
| `intro to me` | **보존** | 뒤에 임의 단어 |
| `outro music` | **보존** | 뒤에 임의 단어 |
| `절망마저` | **보존** | `절` 로 *시작*하지만 접미가 숫자 규칙 위반 |

핵심: **확신이 없으면 지우지 않는다(fail-safe = 보존).** 짧은 괄호 줄이라도 내용이 있으면 남는다.

### 3.3 N11 — 추임새(애드립)는 슬라이드에 넣지 않는다

가수는 노래 사이에 `Yeah`, `Woah`, `Ooh` 같은 **추임새**를 넣는데, 가사 사이트는 그걸 대괄호로
적어 둡니다(`(Yeah, woah, yeah)`). 그대로 두면 추임새가 **한 슬라이드를 차지**하고, 두 줄씩 묶는
기준까지 밀려서 진짜 첫 줄이 둘째 슬라이드로 갑니다.

| 입력 | 결과 | 이유 |
| --- | --- | --- |
| `(Yeah, woah, yeah)` | **줄 삭제** | 대괄호 안이 추임새뿐 |
| `나의 손으로 창조하였노라 (Woah)` | `나의 손으로 창조하였노라` | 괄호만 제거 |
| `하나님께서 바라보시며 oh` | `하나님께서 바라보시며` | 한글이 남는 줄의 꼬리 추임새 |
| `사랑해요 (사랑해요 영원히)` | **그대로** | 괄호 안이 실제 단어(가사) |
| `Oh yeah` | **그대로** | 영어 줄은 건드리지 않는다 |
| `(...)` | **줄 삭제** | 내용 없는 장식 |

즉 **추임새 목록에 있는 단어만** 지웁니다(`yeah`, `woah`, `oh`, `ooh`, `hey`, `la`, `na` …).
괄호 안에 실제 가사가 있으면 그대로 남습니다. 이 규칙은 웹 수집·`lrclib`·직접 붙여넣기 **모두**에 적용됩니다
(미리보기와 실제 빌드가 같은 코드를 쓰기 때문 — 규칙 M1).

### 3.4 페어링 (`text/split.py`)

- 정리된 줄을 **순서대로 2개씩** 묶는다. 슬라이드 수 = `ceil(줄수 / 2)`.
- 줄이 홀수면 마지막 페어는 `(마지막줄, None)` → 마지막 슬라이드에 1줄만.
- 빈 줄은 이미 사라졌으므로 "빈 줄이 슬라이드를 먹는" 일은 없다.
- 줄이 0개면 빌드가 `EmptyLyricsError`(exit 3)로 멈춘다(빈 pptx 방지).

**후렴 줄이 너무 많을 때**: `--dedupe-chorus`(또는 웹 체크박스)는 **서로 떨어진** 동일 줄도
3회 이상이면 **앞의 2회만** 남긴다(기본 꺼짐 — 원문 보존이 기본). N8(연속 3회)과는 별개다.

## 4. 배경은 20종이 순환한다

```
bg_index = pool[ k % len(pool) ]        k = 0-based 출력 순서
```

- `pool` = 템플릿의 **슬라이드 번호 순서 그대로** (기본: 0,1,2,…,19).
- `--skip-slide N`(1-based, 반복 가능)으로 특정 배경을 풀에서 뺄 수 있다. 풀 구성만 바뀌고
  코드는 그대로다.
- 슬라이드 수가 배경 수를 넘으면 **처음 배경으로 되돌아가 반복**한다(예: 21장 출력 → 21번째가 `pool[0]`).
- 각 슬라이드의 텍스트 서식(`제목 1` 의 `rPr`)은 **그 배경 슬라이드의 것을 상속**한다(배경마다
  글꼴 크기가 다를 수 있음 — 템플릿에서 슬라이드19 는 6600, 나머지는 7200 확인).
- 웹 미리보기 상단의 "배경 순환: template 1 → 20 순서로 반복" 표기가 이 규칙이다.

## 5. 결과가 기대와 다를 때 — 확인 순서

| 증상 | 먼저 확인 | 원인/대처 |
| --- | --- | --- |
| 가사 줄이 사라짐 | 그 줄이 N6 마커 형식인가? | `verse`/`절` 등으로 *시작*해도 접미가 숫자가 아니면 보존된다. 그래도 사라지면 N8(연속 3회)·N9(줄끝 `-~|`)·`--dedupe-chorus` 를 끄고 비교 |
| `[Verse]` 같은 표시가 안 지워짐 | 대괄호 밖에 글자가 있는가 | `[Verse] blah` 처럼 마커가 전용 줄이 아니면 보존된다(의도된 동작) |
| 마지막 슬라이드가 1줄 | 정상 | 줄 수가 홀수다 |
| 배경이 안 보이거나 잘못 나옴 | `--skip-slide` 값, 템플릿 장수 | `--doctor` 의 `pool`/`slide_count` 확인 |
| 노트가 없음 | 기본값 | 노트는 기본 복제 안 함(`--keep-notes` / `LYRICS2PPTX_KEEP_NOTES=1`) |
| 글자가 슬라이드 밖으로 넘침 | `normAutofit` | 채우기 단계에서 항상 `normAutofit` 를 넣는다(PowerPoint 가 넘칠 때 자동 축소). 그래도 안 되면 템플릿 도형 크기 확인 |
| 파일이 안 열림 | `--strategy zip` 시도 | 방식 A(`parts`) 폴백 F1 이 자동 동작. 강제로 `zip` 으로 우회 |
| 실패 원인을 모르겠음 | `python -m lyrics2pptx.cli --doctor` | 템플릿/전략/소스 진단(읽기 전용) |
| 로그를 더 보고 싶음 | `--log-level DEBUG` | 상세 로그는 stderr 로 |

**자주 쓰는 진단**:

```powershell
python -m lyrics2pptx.cli --doctor
python -m lyrics2pptx.cli --query "…" --strategy zip
$env:LYRICS2PPTX_LOG_LEVEL="DEBUG"; python -m lyrics2pptx.cli --input-file "가사.txt"
```
